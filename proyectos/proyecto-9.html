año 2026

¿Qué es este proyecto?

Nutrición Especializada es un sistema desarrollado para un cliente real que automatiza los procesos que hasta ahora se llevaban en hojas de Excel: punto de venta con notas de remisión, inventario semanal, cartera de clientes y proveedores, y flujo de caja y bancos.

La base de datos en PostgreSQL concentra buena parte de la lógica: triggers que descuentan el inventario al vender, recalculan saldos y registran una bitácora de auditoría. Sobre ella, una API REST en Express con TypeScript y un frontend en Angular con menú y rutas filtrados por permisos.

Módulos del sistema

Dieciséis módulos de negocio expuestos por la API y con pantalla en el frontend:

Punto de venta Notas de remisión con cliente, renglones, direcciones de entrega, totales y PDF para imprimir
Inventario Kárdex y foto semanal, descuento automático al vender, ajustes y mermas con motivo obligatorio
Clientes y precios Catálogo de clientes, precios de lista y precios especiales por cliente sin traslape
Proveedores y compras Compras por bulto y kilo, alta automática en inventario y saldo del proveedor
Pagos y cartera Abonos aplicados a notas con validación de saldos y estado de cuenta por cliente
Caja y bancos Cuentas, ingresos y egresos, resumen por periodo y cierre diario esperado
Facturación Factura una o varias notas con reglas para evitar duplicados y cancelación con motivo
Reportes y Excel Existencia, consumo semanal promedio y estado de cuenta, con hoja de Excel por cliente o masiva
Usuarios, roles y permisos Control de acceso por permisos (RBAC) con roles de Administrador, Empleada y Cajera
Auditoría Bitácoras de accesos, caja, inventario y precios con valores antes y después, solo lectura
Catálogos Especies, categorías, almacenes y direcciones de entrega editables desde la app

Lo que aprendí

Este proyecto me enseñó a llevar la integridad del negocio a la base de datos: triggers para folios, inventario y saldos, restricciones que obligan a justificar ajustes y cancelaciones, y auditoría automática que sabe qué usuario hizo cada cambio. Del lado de la API trabajé con transacciones y bloqueos (SELECT … FOR UPDATE) para evitar que dos operaciones simultáneas se pisen el saldo de una cuenta.

También diseñé un modelo de roles y permisos que gobierna tanto las rutas de la API como el menú del frontend, generé PDF fieles a la plantilla de Excel del negocio y aprendí a sostener el sistema con una suite de pruebas reejecutable contra una base aparte. Todo al servicio de un cliente real, con requisitos que cambian y datos que importan.
